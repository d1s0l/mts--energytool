# MTS Energytool

Каркас проекта: frontend, FastAPI и PostgreSQL. Бизнес-логика пока не реализована.

## Запуск через Docker

```sh
docker compose up --build
```

- Frontend: http://localhost:8080
- Swagger: http://localhost:8000/docs
- OpenAPI: http://localhost:8000/openapi.json

PostgreSQL хранит данные в volume `pgdata`. При старте backend открывает пул
подключений к БД и применяет SQL-миграции. Прикладные эндпоинты, модель и RAG пока отсутствуют.
В Swagger пока нет прикладных операций. Frontend не подключён к backend.

Для изменения локального пароля скопируйте `.env.example` в `.env` в корне.
Пароль по умолчанию предназначен для локальной разработки. При смене пароля
существующего PostgreSQL нужно также изменить пароль роли в самой БД.

## Backend локально

Используйте Python 3.12 (та же версия, что в Docker).

```sh
cd backend
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
cp .env.example .env
```

Из корня проекта запустите БД с локальным портом:

```sh
docker compose -f compose.yaml -f compose.local.yaml up -d postgres
```

Затем из `backend/`:

```sh
uvicorn app.main:app --reload
ruff check .
```

При изменении пароля согласуйте DATABASE_URL в `backend/.env` с корневым `.env`.
Интеграционные тесты запускаются из `backend/` на реальном PostgreSQL:

```sh
TEST_DATABASE_URL=postgresql://energytool:energytool@localhost:5432/energytool python -m pytest
```

Используйте тестовую БД: тесты создают и удаляют только свои временные схемы
со случайными именами. Нужны права на создание схем. Без `TEST_DATABASE_URL`
интеграционные тесты пропускаются.

## Структура backend

- `app/main.py` — приложение FastAPI и жизненный цикл пула БД.
- `app/config.py` — настройки окружения.
- `app/db.py` — подключение PostgreSQL.
- `app/migrate.py`, `app/migrations/` — запуск и версии SQL-миграций.
- `app/api/` — место для будущих маршрутов.
- `app/schemas.py` — место для моделей запросов и ответов.
- `app/consultant.py`, `app/rag.py` — места для будущих интеграций.
- `solution.py` — заготовка адаптера для платформы, пока не выполняет сабмит.

Контракты API, дальнейшие изменения схемы БД, интеграция LLM/RAG и формат сабмита требуют согласования.
LLM SDK, LangGraph и векторная БД пока не добавлены: выбор зависит от команды.

## Хранение данных

- `sessions`: UUID, состояние, время создания.
- `messages`: UUID, сессия, порядок, роль, текст, JSONB-метаданные отладки и время.
- `leads`: UUID, сессия, ФИО, телефон, компания, резюме и время создания.
- `schema_migrations`: применённые миграции и их контрольные суммы.

Сообщения и заявки ссылаются на существующую сессию. Каскадного удаления нет:
БД не позволяет удалить сессию с историей. Сессия может существовать без
сообщений и заявки. Количество заявок на сессию пока не ограничено.
JSONB позволяет уточнять метаданные отладки без изменения таблицы.
Проверка формата телефона и переходы состояний будут реализованы отдельно.

Миграции применяются при старте backend в транзакции с блокировкой параллельных
запусков. Повторный запуск не очищает таблицы. При ошибке изменения текущего
запуска миграций откатываются, приложение не запускается.

Для изменения структуры добавляйте следующий файл, например
`backend/app/migrations/002_add_field.sql`. Уже применённые файлы не редактируйте:
проверка контрольной суммы остановит запуск. Исправления вносятся следующей
миграцией; автоматического отката версий нет. Перед изменением рабочей БД
делайте резервную копию.
