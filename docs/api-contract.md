# Изменения ядра

Актуальные дополнения к этому контракту: [consultant-core.md](consultant-core.md).
Доступ к сессии теперь требует `X-Session-Token`, общий просмотр — служебного
Bearer-токена. Сообщения принимают `client_message_id` и возвращают `status`;
для корректировки контактов доступен `PUT /api/sessions/{id}/lead`.

# API-контракт: черновик для согласования


## Эндпоинты

| Метод | Путь | Результат |
|---|---|---|
| POST | `/api/sessions` | Создать сессию |
| DELETE | `/api/sessions/{session_id}` | Удалить чат из списка |
| GET | `/api/sessions` | Список сессий |
| GET | `/api/sessions/{session_id}` | История и состояние сессии |
| GET | `/api/sessions/{session_id}/debug` | Сохранённые метаданные ответов ассистента |
| POST | `/api/sessions/{session_id}/messages` | Отправить сообщение и получить ответ |
| POST | `/api/sessions/{session_id}/lead` | Передать контакты и создать заявку |
| GET | `/api/sessions/{session_id}/lead` | Получить заявку |
| GET | `/api/health` | Готовность сервиса |


## Состояние сессии

- `chatting` — обычная консультация.
- `awaiting_contacts` — консультант предлагает оставить заявку, можно показать форму.
- `lead_created` — заявка сохранена.


## Создание сессии

`POST /api/sessions`, без тела. Ответ `201`:

```json
{
  "id": "11111111-1111-4111-8111-111111111111",
  "state": "chatting",
  "created_at": "2026-11-10T09:00:00Z"
}
```


## Список сессий

`GET /api/sessions?limit=20&offset=0`. Ответ `200`:
Поле `first_message` содержит текст первого сообщения пользователя в порядке
истории, включая сообщения с ошибкой генерации. Если таких сообщений нет — `null`.

```json
{
  "items": [
    {
      "id": "11111111-1111-4111-8111-111111111111",
      "state": "chatting",
      "created_at": "2026-11-10T09:00:00Z",
      "first_message": "Как подобрать солнечную станцию?"
    }
  ],
  "total": 1,
  "limit": 20,
  "offset": 0
}
```


## Данные для Debug Mode

`GET /api/sessions/{session_id}/debug` возвращает `session_id` и массив `items`.
Элемент содержит `role`, `message_id`, `created_at` и сохранённый объект `debug`.
Для ответов ассистента он включает время поиска, генерации и обработки, `sources`,
`raw_response` (текст `choices[0].message.content` до JSON-разбора),
`parsed_response` (JSON после разбора), `validation_errors` и `final_response`
(текст, отправленный клиенту). Если генерация завершилась ошибкой после получения
текста модели, диагностический элемент связан с неудавшейся пользовательской
репликой (`role: "user"`). При штатной repair-попытке `raw_response` содержит
последний ответ, а `raw_response_attempts` сохраняет тексты обеих попыток.
Порядок элементов совпадает с историей. Для пустого
чата `items: []`; у старых сообщений новые поля могут отсутствовать или быть `null`.
Обычные endpoints истории и отправки сообщения не возвращают новые поля raw-отладки.
Поиск и модель при GET debug повторно не вызываются.
Доступ: `X-Session-Token` владельца или служебный Bearer-токен.
Удалённая сессия возвращает 404; для её просмотра доступен `include_deleted=true`.

## Отправка сообщения

`POST /api/sessions/{session_id}/messages`:

```json
{
  "text": "У нас три склада, с чего начать?"
}
```


```json
{
  "session_id": "11111111-1111-4111-8111-111111111111",
  "state": "chatting",
  "user_message": {
    "id": "33333333-3333-4333-8333-333333333333",
    "role": "user",
    "text": "У нас три склада, с чего начать?",
    "created_at": "2026-11-10T09:02:00Z",
    "debug": null
  },
  "assistant_message": {
    "id": "44444444-4444-4444-8444-444444444444",
    "role": "assistant",
    "text": "Какая задача сейчас главная: снизить счета или найти потери?",
    "created_at": "2026-11-10T09:02:02Z",
    "debug": {
      "total_ms": 2000,
      "search_ms": 150,
      "generation_ms": 1750,
      "sources": [
        {
          "document_id": "document-id",
          "title": "Название документа",
          "fragment_id": "fragment-id",
          "fragment": "Текст фрагмента, переданного консультанту",
          "score": null
        }
      ]
    }
  }
}
```


### Метаданные отладки

- `total_ms` — время от входа в обработчик до записи ответа, включая чтение истории, поиск и генерацию.
- `search_ms` и `generation_ms` — замеры модулей; `null`, если замер недоступен.
- `sources` — фрагменты, фактически переданные консультанту для ответа;
  пустой массив, если их не было. Не весь список кандидатов поиска.
- `score` — необязательная оценка RAG, число или `null`; её смысл и шкалу определяет
  RAG-команда. Frontend не должен интерпретировать её как вероятность правильного ответа.

## Ошибки

Предлагаемый единый формат, включая ошибки валидации FastAPI:

```json
{
  "error": {
    "code": "session_not_found",
    "message": "Диалог не найден",
    "details": []
  }
}
```

`details` — список ошибок полей; пустой для ошибок без привязки к полю.
Элемент ошибки поля: `{"field": "phone", "message": "Описание ошибки"}`.
Frontend ориентируется на HTTP-статус и `code`, текст предназначен пользователю.

| HTTP | code | Когда |
|---|---|---|
| 404 | `session_not_found` | Сессия не существует |
| 404 | `lead_not_found` | Заявка отсутствует |
| 409 | `session_busy` | В сессии уже выполняется операция |
| 409 | `lead_already_exists` | Попытка заменить контакты существующей заявки |
| 422 | `validation_error` | Неверный UUID, поля, параметры или пустое сообщение |
| 503 | `consultant_unavailable` | Консультант или необходимый поиск недоступен |
| 503 | `storage_unavailable` | Хранилище недоступно |
| 504 | `consultant_timeout` | Превышен срок обработки консультантом |
| 500 | `internal_error` | Непредвиденная ошибка сервера |

Отказ консультанта из-за отсутствия сведений в базе — нормальный ответ `200`,
а не техническая ошибка. Stack trace и секреты пользователю не возвращаются.

## Готовность сервиса

`GET /api/health`: `200`, если необходимые зависимости готовы; `503` иначе.

```json
{
  "status": "not_ready",
  "checks": {
    "database": "ready",
    "consultant": "not_configured",
    "rag": "not_configured",
    "lead_summarizer": "not_configured"
  }
}
```



## Удаление чата

`DELETE /api/sessions/{session_id}` возвращает `204` без тела.
Чат помечается временем `deleted_at` и исчезает из обычного списка.
Сообщения и заявки сохраняются для проверки истории.
Повторное удаление возвращает `204`, неизвестный ID — `404`,
занятая обработкой сообщения сессия — `409 session_busy`.

Для просмотра сохранённых данных доступны
`GET /api/sessions?include_deleted=true` и
`GET /api/sessions/{session_id}?include_deleted=true`.
По умолчанию получение удалённого чата и отправка сообщения в него возвращают `404`.
В ответах сессий поле `deleted_at` равно `null` для активного чата.


## Правила API заявок

POST принимает full_name (1–200 символов), company (1–300) и phone.
Пробелы по краям удаляются. Телефон содержит 10–15 цифр с необязательным +;
пробелы, скобки и дефисы удаляются перед сохранением и сравнением контактов.
Точные правила проверки телефона можно изменить после согласования с frontend.

Для создания нужна хотя бы одна пользовательская реплика в истории.
Пустой диалог возвращает 422 empty_dialog. Резюме создаёт подключённый модуль
модели по сохранённой истории. До его подключения возвращается 503
consultant_unavailable, при превышении 60 секунд — 504 consultant_timeout.

Первое создание возвращает 201. Заявка и состояние lead_created записываются
одной транзакцией. Повтор с теми же контактами возвращает существующую заявку
с 200, с другими — 409 lead_already_exists. Одновременная операция в сессии
возвращает 409 session_busy. Эти правила действуют для новых заявок через API.
Если в старых данных несколько заявок сессии, GET возвращает последнюю.

GET без заявки возвращает 404 lead_not_found, неизвестная или удалённая сессия —
404 session_not_found. Заявку удалённой сессии можно прочитать через
GET /api/sessions/{session_id}/lead?include_deleted=true.


## Проверка готовности

GET /api/health выполняет SELECT 1 в PostgreSQL с ограничением ожидания 2 секунды.
RAG готов, если индекс построен и содержит фрагменты. Работающий локальный поиск
считается готовым даже при недоступности эмбеддингов.

Поля consultant и lead_summarizer проверяют подключение вызываемых модулей.
Внешний API модели этим запросом не вызывается, поэтому ready для этих полей
означает наличие подключённой реализации, а не подтверждение доступности провайдера.

Ответ 200 и status ready возвращаются, когда все четыре проверки имеют ready.
Иначе возвращаются 503 и status not_ready. Отсутствующая зависимость имеет
not_configured, ошибка проверки существующей — not_ready. Ответ не содержит
адресов БД, ключей или текстов внутренних исключений.

Проверка доступна после запуска приложения. Ошибки начальной миграции или
загрузки базы знаний останавливают запуск приложения.
