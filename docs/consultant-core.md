# Ядро консультанта

Общее ядро `backend/consultant_impl.py` подключено к FastAPI и CSV-сабмиту.
Генерация использует обычный `/chat/completions`; специальных возможностей
structured outputs и tool calling не требует. Контракт JSON проверяется приложением,
при нарушении разрешён один ремонт ответа. Неудача не превращается в выдуманный ответ.

## Настройка

Для API и сабмита задайте `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`.
Поддержаны альтернативы `OPENAI_BASE_URL`, `OPENAI_API_KEY`, `OPENAI_MODEL`/`GEN_MODEL`.
Адрес уже содержит необходимый префикс (например `/v1`); второй префикс не добавляется.
`TEMPERATURE`, `MAX_TOKENS`, `MAX_WORKERS`, `LLM_TIMEOUT` задают генерацию и нагрузку.
Без URL, ключа или идентификатора генератора веб-сервис сообщает неготовность,
а CSV-команда завершает запуск с ошибкой настройки. Фиксированной генеративной модели нет.
Не используйте реальные персональные данные на хакатоне.

RAG настраивается прежними переменными `RAG_MODE`, `EMB_MODEL`, `RERANKER_MODEL`,
`TOP_K`, `RERANKER_TOP_N`. Документы читаются целиком; ограничения выбранных продуктов
передаются отдельно от основного рейтинга. Текстовые таблицы сохраняются более крупными
блоками, чтобы числа не отделялись от условий. Размер prompt ограничен символами;
проверка реального токенного бюджета Qwen остаётся частью прогона с прокси.

## Доступ к API

Создание `POST /api/sessions` доступно анонимно и возвращает `access_token` один раз.
Для последующих операций этой сессии передавайте заголовок `X-Session-Token`.
В БД сохраняется только SHA-256 токена. Сессии, созданные до миграции, доступны
через служебный доступ. UUID сам по себе не даёт доступ к данным.

Для просмотра всех сессий задайте секрет `API_ACCESS_TOKEN` и передавайте
`Authorization: Bearer <API_ACCESS_TOKEN>`. Этот служебный токен разрешает также
проверку истории и заявок всех сессий; его нельзя передавать посетителям сайта.
Отсутствие настройки не открывает общий список. Health остаётся публичным.

Контракт доступа изменился: клиентской части необходимо сохранять токен новой сессии
и прикладывать его к запросам. Код фронтенда в этой ветке не менялся.

## Сообщения и история

В `POST /api/sessions/{id}/messages` кроме `text` передавайте UUID `client_message_id`.
Повтор с тем же ID и текстом возвращает прежнюю завершённую пару сообщений.
Другой текст с тем же ID получает 409. После ошибки тот же ID позволяет повторную
попытку с прежним текстом. Старые клиенты могут не передавать ID, но тогда
повторная доставка не распознаётся как повтор.

Входящее сообщение сохраняется до вызова модели. `status` в истории принимает
`processing`, `completed`, `failed`. При сбое вопрос остаётся доступен проверяющему.
Неудачные обращения не подмешиваются в следующую консультацию как завершённые ходы.
Во время обработки соединение БД не удерживается. Короткая транзакция резервирует
сессию через processing token; после сбоя процесса резерв может быть перехвачен
через 180 секунд. Одновременный новый ход получает 409.

История не переносится между сессиями или CSV ID. Для диалога, превышающего текущий
бюджет 24 000 символов, ассистент просит сузить задачу в новом диалоге вместо
незаметного отбрасывания старых фактов. Структурированное сжатие памяти — дальнейшее
улучшение; текущая версия использует исходные реплики.

## Заявки

Ассистент может предложить собрать ФИО, телефон и компанию. Проверяется, что контакты
действительно встречались в пользовательских сообщениях, а не были сочинены моделью.
При полном наборе и намерении клиента ядро возвращает предложение заявки; API
сохраняет её в транзакции с ответом. Только после этого добавляется подтверждение
«Заявка сохранена в прототипе». При изменении контактов через чат обновляется
существующая карточка.

Резюме строится из выбранных моделью дословных цитат клиента: до шести пунктов по
актуальной задаче. Неподтверждённая цитата отклоняется. Для отдельного запроса заявки
доступен тот же выбор цитат; при недоступности модели сохраняется краткая выдержка
последних пользовательских сообщений. Это обеспечивает проверяемость, но требует
ручной оценки полезности резюме на реальных диалогах.

Отдельный `POST /api/sessions/{id}/lead` сохранён. Повтор с теми же контактами
идемпотентен. `PUT /api/sessions/{id}/lead` позволяет исправить контакты.
Реальной отправки менеджерам нет. В CSV-режиме предложение заявки входит в ответ;
хранение карточек в PostgreSQL выполняется только веб-адаптером.

## Сабмит

Из `backend/`: `python build_submission.py --output dist/submission.zip`.
Архив теперь содержит стандартный `consultant_impl.py` автоматически. Параметр
`--consultant` оставлен для явной подмены реализации.

Сабмит строит индекс при запуске и не зависит от PostgreSQL. Строки обрабатываются
независимо; ошибка одной не отменяет остальные. `SUBMISSION_TIMEOUT` задаёт общий
бюджет (по умолчанию 1100 секунд, максимум 1150). После каждого результата атомарно
обновляется корректный CSV. Окончательно не обработанные ID содержат честный текст
о техническом сбое. Это аварийное поведение, а не успешный ответ; ошибки фиксируются
по номеру строки и типу без тела исключения провайдера.

## Проверки и ограничения

Офлайн: `python -m unittest discover -s backend/tests -p test_consultant_core.py -v`.
Поиск: из `rag/` — `python -m unittest discover -s tests -v`.
Полный backend: из `backend/` — `TEST_DATABASE_URL=... python -m pytest` после установки
`requirements-dev.txt`. Используйте отдельную тестовую БД.

На текущем стенде прошли 12 новых офлайн-проверок консультанта и batch-обработки,
20 прежних тестов поиска, 40 проверок ожидаемых фрагментов команды. Три найденных
ценовых запроса теперь возвращают ориентир платформы. Проверки с моделью используют
подставные ответы и не доказывают качество Qwen на скрытых вопросах.

Полный backend pytest и PostgreSQL здесь не запущены: зависимости нельзя скачать
из-за недоступного DNS, доступ к Docker socket отсутствует. Проверка реального прокси,
всей схемы API/БД и измерение задержек обязательны перед сдачей.

Числа сверяются с выбранными источниками/словами клиента; ID источников валидируются.
Это не полноценная проверка логического следования: совпадение числа не доказывает,
что оно относится к нужному показателю. Семантические ошибки и полноту оговорок нужно
проверять отдельными диалоговыми оценками. Runtime не использует интернет для ответов.
