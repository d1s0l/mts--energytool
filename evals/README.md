# Сравнение ответов с демо-эталонами

Запуск из корня проекта, Python 3.10+, без дополнительных зависимостей:

```sh
python3 evals/evaluate_answers.py \
  --questions /Users/lil/Downloads/demo_questions.csv \
  --reference /Users/lil/Downloads/demo_output.csv \
  --predictions submission.csv \
  --output-dir evals/reports/latest
```

`submission.csv` — реальные ответы команды, колонки строго `id,answer`.
Строки сопоставляются по ID, а не по порядку. Поддерживаются UTF-8 с BOM,
кавычки и переводы строк внутри CSV. Исходные файлы не изменяются.

Результат:

- `report.html`: вопрос, эталон и наш ответ рядом; сначала ответы с низким сходством.
- `report.json`: полные результаты для автоматической обработки.
- `details.csv`: результаты по каждому вопросу для таблиц.

## Как читать метрики

- Exact match: полное совпадение после удаления пробелов по краям.
- Normalized match: совпадение последовательности слов без регистра, пунктуации,
  с приведением ё к е.
- Token F1: пересечение слов с учётом повторений, баланс полноты и точности.
- ROUGE-L F1: совпадающая последовательность слов с сохранением порядка.
- `check_numbers`: множества чисел различаются. Единицы измерения не проверяются;
  эквивалентные «1 млн» и «1 000 000» тоже могут получить замечание.
- `low_lexical_overlap`: Token F1 ниже 0.5. Это условный порог для ручного просмотра.
- Отдельные флаги: отсутствующий/пустой ответ, более 10 000 символов,
  более рекомендованных 150 слов, возможный технический fallback.

Средние считаются по всем вопросам: отсутствующие и некорректные ответы получают
нулевые метрики. Лишние ID и ошибки колонок делают формат невалидным.
Дублирующиеся ID и повреждённые CSV отклоняются, чтобы не сравнить неверные строки.
Коды завершения: 0 — формат корректен; 1 — отчёт создан, формат ответов невалиден;
2 — ошибка чтения/входных данных. Низкое сходство само по себе не меняет код завершения.

**Это текстовые метрики, а не проверка фактов, семантическая оценка или Score
хакатона.** Ответ с отрицанием может иметь высокое сходство, а правильный пересказ —
низкое. Нельзя интерпретировать 70% Token F1 как 70% правильных ответов.
Эталонов всего 18; не следует подгонять решение под их формулировки.

## Получение реальных ответов

Используйте существующий `backend/solution.py`: он вызывает тот же консультант,
который используется HTTP API, и сохраняет `submission.csv`. В `DATA_DIR` должны
быть `questions.csv` (копия демо-вопросов) и `knowledge-base.zip`.
Модель настраивается через `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`;
перед запуском загрузите их в окружение. Нужны зависимости backend.

```sh
PYTHONPATH=backend:. DATA_DIR=/absolute/path/to/eval-data python3 backend/solution.py
```

Затем выполните команду сравнения выше. При недоступной модели не выдавайте
технические fallback-ответы за проверку качества генерации.

Самопроверка инструмента без модели: передайте `demo_output.csv` также в
`--predictions`. Все метрики должны быть 1. Это проверяет инструмент, а не решение.

```sh
python3 -m unittest discover -s evals/tests -v
```

Отчёты содержат полный текст вопросов и ответов; хранятся локально и исключены из Git.
