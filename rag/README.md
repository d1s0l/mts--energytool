# Поиск по базе знаний EnergyTool

Модуль первой части командного проекта: принимает вопрос и историю диалога, возвращает фрагменты базы знаний и источники. Подключается к серверу и модулю консультанта как обычный Python-модуль. Python 3.10 или новее. Для локального поиска дополнительные зависимости не нужны.

## Что положить в свою ветку

Распакуйте архив в отдельную папку `rag` внутри репозитория. Основной файл для интеграции — `rag/rag_search.py`. Сохраните также тесты, оценочный скрипт и документацию. Архив содержит только код и документацию; предоставленную организаторами базу знаний в публичный репозиторий не добавляйте.

Не заменяйте командные `solution.py`, `requirements.txt`, Dockerfile или сервер. Модуль первой части передаётся ответственному за сервер для подключения к общей точке входа. Этот архив не является готовым сабмитом всей команды.

## Быстрая проверка

В терминале перейдите в распакованную папку и выполните:

```bash
python3 -m unittest discover -s tests -v
python3 rag_search.py --kb /путь/к/knowledge-base.zip --question "Можно ли разместить панели на обоих скатах?"
```

Вместо ZIP можно указать каталог, содержащий только базу знаний. Подкаталоги поддерживаются, относительные пути источников сохраняются. Не указывайте весь репозиторий: его README и другие Markdown-файлы тоже попадут в индекс. Исходные файлы не изменяются. ZIP читается без распаковки.

Локальный режим можно явно включить: `RAG_MODE=local python3 rag_search.py ...`.

## Подключение из Python

Если папка находится в корне репозитория:

```python
from rag.rag_search import KnowledgeSearch, Config

# Один раз при запуске приложения; не создавать заново для каждого сообщения.
searcher = KnowledgeSearch("data/knowledge-base.zip", Config.from_env())

result = searcher.search(
    "А можно начать с части приборов?",
    history=[{"role": "user", "content": "Нужен учёт по арендаторам бизнес-центра"}],
    top_k=6,
)
context_for_consultant = result["hits"]
debug_for_frontend = {
    "search_ms": result["search_ms"],
    "sources": result["sources"],
    "hits": result["hits"],
    "warnings": result["warnings"],
}
```

Для автоматического прогона на платформе скопируйте `rag_search.py` в корень ZIP рядом с командным `solution.py` и импортируйте `from rag_search import KnowledgeSearch`. Регламент автоматической проверки переносит корневые Python-модули; структура репозитория финального прототипа может отличаться. Базу платформа предоставляет отдельно в `DATA_DIR/knowledge-base.zip`. Создание `submission.csv` выполняет общая точка входа, а не этот модуль.

`search()` синхронный. В асинхронном обработчике FastAPI вызывайте его через `await asyncio.to_thread(searcher.search, question, history=history)`, чтобы сетевые обращения не блокировали цикл сервера. Число одновременных запросов ограничивает сервер в соответствии с `MAX_WORKERS`. Разные запросы не переносят историю друг другу. Разрешено использовать один экземпляр между потоками; индекс после построения не изменяется.

## Контракт результата

Результат — словарь, сериализуемый в JSON:

| Поле | Значение |
|---|---|
| `schema_version` | Версия контракта, сейчас 1 |
| `query` | Исходный вопрос |
| `hits` | Упорядоченные найденные фрагменты |
| `sources` | Уникальные относительные пути источников в порядке выдачи |
| `timing_ms` | Время локального поиска, эмбеддингов, слияния, реранкера, отбора и общее время; отключённые этапы равны 0 |
| `search_ms` | Время одного поиска, включая сетевые этапы, если они выполнялись |
| `mode` | `local` или `hybrid`, фактически использованный поиск |
| `reranked` | Применён ли реранкер |
| `warnings` | Обезличенные коды ошибок и перехода к локальному поиску |
| `needs_review` | `true`, если выдача пустая. `false` не доказывает наличие ответа |
| `score_kind` | Указание, что баллы слияния не являются вероятностью |

Каждый элемент `hits`: `chunk_id`, `source`, `title`, `section`, `text`, `line_start`, `line_end`, `rank`, `score`, `lexical_score`. Номера строк начинаются с 1; конец включён. `text` — исходные строки с удалением пробелов по краям, без генерации или пересказа. `chunk_id` детерминирован для неизменного файла, пути и разбиения. При изменении базы или параметров ID могут измениться. После реранкера поле `rank` отражает окончательный порядок, `score` сохраняет исходный балл слияния.

Время построения индекса и его размер доступны в `searcher.info`; это не время ответа пользователю. Общее время ответа измеряет сервер, включая генерацию.

## Как устроен поиск

1. Чтение UTF-8/UTF-8 BOM Markdown и TXT из каталога или ZIP.
2. Разбиение по заголовкам, абзацам и исходным строкам. Короткий вводный раздел сохраняется вместе с дочерними пунктами. Заголовки внутри fenced code block не считаются разделами. Длинные разделы делятся с перекрытием строк. Таблицы не преобразуются в пересказ; часть длинной таблицы может оказаться в нескольких фрагментах, поэтому заголовок раздела всегда передаётся отдельно. Единичная строка длиннее лимита сохраняется целиком: `chunk_chars` — целевой, не жёсткий размер.
3. BM25 по словам с простой нормализацией русских окончаний и небольшим открытым словарём терминов. Дополнительно применяется поиск по символьным четырёхграммам TF-IDF. Это помогает при различиях словоформ, но не заменяет полноценное понимание языка.
4. При наличии API — косинусная близость эмбеддингов всех фрагментов. Ранжирования объединяются через Reciprocal Rank Fusion с дополнительным нормированным вкладом BM25. При поиске учитываются совпадения с заголовками, расширения намерения запроса и мягкие тематические приоритеты. Они определяются по названию документа, а не его имени файла; другие документы не исключаются из поиска. Опциональный реранкер пересортировывает кандидатов. Сильно перекрывающиеся фрагменты одного источника удаляются из выдачи.

Для диалога извлекаются последние пользовательские реплики; последняя реплика дополнительно ищется отдельно. Поддерживаются список `history` и текст платформы с маркерами `Пользователь:` / `Ассистент:`. Ответы ассистента исключаются из поискового запроса, чтобы не усиливать его возможные ошибки. Полного переписывания анафор («а это?», «сколько тогда?») без LLM нет: модуль консультанта может передать самостоятельный поисковый вопрос с уточнёнными сущностями.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `RAG_MODE` | `auto` | `local`: без сети; `auto`/`hybrid`: попробовать эмбеддинги при наличии адреса и ключа, при ошибке использовать локальный поиск |
| `LLM_BASE_URL`, иначе `OPENAI_BASE_URL` | пусто | Базовый URL прокси организатора; сохраняется переданный префикс, например `/v1` |
| `LLM_API_KEY`, иначе `OPENAI_API_KEY` | пусто | Ключ из окружения; не сохраняется в файлы и не выводится в диагностику |
| `EMB_MODEL` | `BAAI/bge-m3` | Используйте значение платформы |
| `RERANKER_MODEL` | пусто | При пустом значении реранкер выключен; для его включения укажите идентификатор организаторов |
| `RERANKER_TOP_N` | 30 | Запрашиваемое число результатов реранкера; ограничивается размером пула |
| `TOP_K` | 6 | Число выдаваемых фрагментов, можно переопределить в `search()` |
| `RAG_CANDIDATES` | 30 | Размер промежуточного пула, не меньше запрошенного top_k |
| `RAG_CHUNK_CHARS` | 1800 | Целевой размер фрагмента |
| `RAG_OVERLAP_CHARS` | 240 | Перекрытие целыми строками |
| `RAG_API_TIMEOUT` | 15 | Тайм-аут одного HTTP-обращения, секунды |
| `RAG_API_RETRIES` | 1 | Повторы после первой попытки, от 0 до 2 |

Параметр `CHUNKER` платформы намеренно не используется: в модуле выбран собственный способ разбиения. Переменные генерации `LLM_MODEL`, `MAX_TOKENS`, `TEMPERATURE`, `DATA_DIR` обрабатывает вызывающий код.

API: `POST {base_url}/embeddings` с `model,input`; `POST {base_url}/rerank` с `model,query,documents,top_n`. Эмбеддинги строятся пакетами по 32 фрагмента один раз при старте. Векторы запросов кэшируются в памяти, максимум 128 запросов. На диск кэш не записывается. При отказе построения векторного индекса экземпляр остаётся локальным до перезапуска. HTTP 401/403 не повторяются; сетевые ошибки, 429 и некоторые 5xx повторяются ограниченно.

## Проверка качества

```bash
python3 evaluate_retrieval.py --kb /путь/к/базе --questions /путь/demo_questions.csv > retrieval_report.json
```

Скрипт оценивает наличие ожидаемого факта по открытым регулярным выражениям в top-6. Они находятся только в оценочном скрипте; поисковый модуль не использует ID вопросов или эталонные ответы. Демо-вопросы использованы для разработки, поэтому это development-проверка, не независимый тест и не прогноз оценки LLM-судьи. Отчёт содержит тексты исходной базы: храните его локально, не публикуйте.

Результаты выполненных проверок и ограничения описаны в `QUALITY_REPORT.md`.

## Границы ответственности

Модуль не генерирует ответы, не собирает заявки, не хранит сессии и не запускает веб-сервер. Доверять найденному тексту как инструкции нельзя: консультант должен передавать его как данные, соблюдать ограничения базы, проверять достаточность фактов, задавать уточнения и отказывать при отсутствии ответа. Наличие совпадения и высокий `score` не являются подтверждением истинности или достаточности контекста. Порог достоверного отказа без отдельной размеченной выборки не заявляется.

Перед публичным показом сервер должен решить, какие поля отладки доступны пользователю: `query` может содержать контакты, а фрагменты — непубличные материалы кейса. Модуль читает локальную базу и передаёт данные только настроенному API; в режиме `local` сетевых обращений нет.

## Изменения во второй версии

Из предыдущего варианта перенесены подходы к уточнению поискового запроса, учёту заголовков и тематике документов. Добавлены измерения этапов `timing_ms`; прежние поля `hits`, `sources` и `search_ms` сохранены. Поле `score_kind` уточняет новый способ расчёта балла. Объединение пересекающихся групп синонимов теперь сохраняет все связи. Появилась проверка файлов с изменёнными именами.

Дополнительный прогон найденных при сравнении случаев:

```bash
python3 evaluate_extra.py --kb /путь/к/базе
python3 evaluate_regressions.py --kb /путь/к/базе
```

Эти запросы также использованы при доработке и считаются development-данными. Усреднённое улучшение не означает, что порядок стал лучше для каждого вопроса.
