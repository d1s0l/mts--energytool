# Проверка модуля поиска версия 2

10 ноября 2026 года. Python 3.12.14, Linux. База: 19 предоставленных Markdown-документов EnergyTool. Индекс: 264 фрагмента.

## Что изменилось

Уточнение поисковых намерений короткими расширениями; мягкий приоритет тематики по названию документа; совпадения заголовков; поиск по префиксам слов; нормированный вклад BM25 при слиянии. Символьный поиск, векторный индекс всей базы, кэш, проверки API и локальный резервный режим сохранены. Добавлены timing_ms и проверки новых случаев. Словари пересекающихся групп теперь объединяются, а не перезаписываются.

## Дополнительные проверки

- 20 автоматических тестов пройдены.
- Дополнительные формулировки из evaluate_extra.py: 12/12 с нужным фактом в top-6.
- Ещё 10 формулировок из evaluate_regressions.py: 10/10 с нужным фактом в top-6. Этот набор сначала выявил ухудшение запроса о фамилиях жильцов; после расширения запроса понятием персональных данных случай проходит. Это регрессионный набор, не независимая выборка.
- ZIP и каталог поддерживаются; фрагменты ссылаются на исходные строки, а исходная база не меняется. Проверки этих свойств проходят повторно.
- Переименование исходного документа не отключает тематический приоритет: используется заголовок, а не фиксированное имя файла.

## Ограничения

Все три набора использованы для разработки. Проверки находят текст с ожидаемым фактом, а не оценивают готовую консультацию или полноту ответа. Они не доказывают качество на скрытой выборке и не гарантируют оценку LLM-судьи. Внешние API организаторов не доступны в текущем окружении; форматы успешных ответов и отказов проверены контролируемыми подменами. Нужен интеграционный прогон с настоящими моделями после получения доступа.

Приведённые миллисекунды относятся к локальному поиску на небольшой базе. Работа с API и генерация будут дольше. Значения score — смесь RRF и нормированного BM25, не вероятность. Порог достаточности контекста не заявлен. Контролировать факты, уточнять запрос и формировать отказ должен модуль консультанта.
